# DURE Context

이 문서는 DURE에서 사용하는 용어의 의미를 고정하기 위한 기준 문서다. 화면별 기능과 데이터 계약은 `api-spec.md`를 따르고, 기술 구조는 `architecture.md`를 따른다. 대화와 구현 문서에서 아래 용어를 일관되게 사용한다.

## 용어 원칙

- 상위 운영 단위는 항상 `그룹`이라고 부른다.
- 수업에 참여하는 대상은 항상 `참여자`라고 부른다.
- 참여자는 시스템에 로그인하는 사용자가 아니다.
- 수업을 진행하고 기록을 남기는 사용자는 `강사`라고 부른다.
- 운영 권한을 가진 사용자는 `운영자`라고 부른다.
- 이전 디자인 산출물이나 대화에 남아 있는 다른 라벨은 구현 시 `그룹`, `참여자` 기준으로 치환한다.

## 핵심 용어

| 용어 | 영문 기준 | 의미 |
| --- | --- | --- |
| 워크스페이스 | Workspace | 한 사용자가 만드는 최상위 운영 공간. 그룹, 수업, 참여자, 운영자 권한은 워크스페이스 안에 속한다. |
| 그룹 | Group | 수업과 참여자를 묶는 운영 단위이자 권한 범위. 기업, 지점, 센터, 팀 등 다양한 현실 단위를 포괄한다. |
| 수업 | Course/Class | 기간과 회차를 가진 교육 과정. 단발성 수업은 회차가 1개인 수업으로 다룬다. |
| 회차 | Session | 특정 날짜와 시간에 진행되는 수업 단위. 출석 기록과 수업 메모가 회차에 연결된다. |
| 참여자 | Participant | 수업에 참여하는 대상 데이터. 로그인, 자료 열람, 메모 열람을 하지 않는다. |
| 강사 | Instructor | 수업에 직접 배정되어 자료, 출석, 특이사항, 수업 메모를 기록하는 사용자. |
| 대표 운영자 | Owner Admin | 워크스페이스 전체 권한을 가진 운영자. 권한 설정과 전체 데이터 접근이 가능하다. |
| 그룹 운영자 | Group Admin | 대표 운영자가 지정한 그룹 범위 안에서만 접근 가능한 운영자. |
| 수업 자료 | Material | 수업에 연결된 파일 자료. 공개 그룹 목록과 확인 상태를 가진다. |
| 수업-참여자 배정 | Course Participant Assignment | 특정 참여자가 특정 수업에 참여한다는 연결 정보. 다중 그룹 수업에서는 수업 내 참여 그룹 목록을 함께 가진다. |
| 일반 일정 | General Schedule Item | 캘린더에 표시되는 운영 일정. 수업, 회차, 출석, 수업 메모와 연결되지 않는다. |
| 출석 기록 | Attendance Record | 특정 회차에서 특정 참여자의 출석 상태와 특이사항을 남긴 기록. |
| 수업 메모 | Class Memo | 특정 회차에 대해 남기는 수업 진행 메모. |
| 헤더 최근 활동 | Header Recent Activity | 별도 알림센터 없이 헤더 아이콘에서 보여주는 권한 필터가 적용된 최근 활동. |

## 역할 맥락

### 대표 운영자

워크스페이스 전체 책임자다. 모든 그룹과 수업을 볼 수 있고, 사용자 초대와 권한 설정을 관리한다.

### 그룹 운영자

대표 운영자가 지정한 그룹만 관리한다. 그룹 운영자는 권한이 없는 그룹의 수업, 참여자, 자료, 기록을 볼 수 없다. 그룹 운영자는 새 그룹을 만들거나 그룹을 비활성화/삭제하지 않는다. 그룹 운영자는 자신이 생성했고 자기 접근 그룹에만 속한 참여자의 이름과 메모만 수정할 수 있다.

### 강사

수업에 직접 배정된다. 강사는 그룹에 배정되는 것이 아니라 수업에 배정된다. 강사는 담당 수업의 자료와 회차별 기록을 작성한다. 강사는 일반 일정을 보거나 관리하지 않는다.

### 참여자

운영 대상 데이터다. 참여자는 여러 그룹과 여러 수업에 동시에 속할 수 있다. 참여자는 로그인하지 않고, 화면을 보지 않고, 자료나 수업 메모에 접근하지 않는다.

## 관계 맥락

- 워크스페이스는 여러 그룹을 가진다.
- 그룹은 여러 수업을 가질 수 있다.
- 그룹은 여러 참여자를 가진다.
- 참여자는 여러 그룹에 속할 수 있다.
- 참여자는 여러 수업에 속할 수 있다.
- 수업은 하나 이상의 그룹에 연결될 수 있다.
- 수업-참여자 배정은 수업, 참여자, 수업 내 참여 그룹 목록을 연결한다.
- 수업은 회차를 가진다.
- 수업 자료는 수업과 공개 그룹 목록에 연결된다.
- 일반 일정은 캘린더 표시용 데이터이며 수업과 연결되지 않는다.
- 출석 기록은 회차와 참여자에 연결된다.
- 수업 메모는 회차에 연결된다.

## 상태 용어

### 수업 상태

- 진행 전
- 진행 중
- 진행 완료

수업 상태는 기본적으로 운영자가 관리한다. 단, 마지막 유효 회차의 종료 시간이 지나면 `진행 완료`로 자동 전환될 수 있다.

### 그룹 상태

- 활성
- 비활성

### 자료 확인 상태

- 확인 미정
- 확인됨

강사가 자료를 업로드, 수정, 교체하면 `확인 미정`이다. 권한 있는 운영자가 현재 자료의 내용과 공개 범위를 확인하고 수업에서 사용할 수 있다고 판단하면 `확인됨`으로 바꾼다. Agent의 검토 제안을 거절해도 자료에는 별도 거절 상태를 추가하지 않고 `확인 미정`을 유지한다.

### 출석 상태

- 출석
- 부분 출석
- 결석

`부분 출석`은 지각 또는 조퇴처럼 수업 전체를 온전히 출석하지 않은 경우를 묶어 기록하는 상태다.

### 회차 노출 상태

- 표시
- 숨김

회차 노출 상태는 캘린더 표시 여부만 결정한다.

### 기록 집계 상태

- 포함
- 제외

기록 집계 상태는 출석률 계산 포함 여부를 결정한다.

## 표현 규칙

- `그룹, 수업, 참여자`는 사이드바의 관리 허브 이름으로 사용한다.
- `그룹 관리`, `수업 관리`, `참여자 관리`는 관리 허브 내부 탭 이름으로 사용한다.
- `참여자 현황`은 수업 상세의 탭 이름으로 사용한다.
- `출석부`는 강사 콘솔에서 회차별 출석을 입력하는 탭 이름으로 사용한다.
- `확인 미정`은 자료가 아직 운영자 검토를 받지 않은 상태를 의미한다.
- `확인됨`은 권한 있는 운영자가 현재 자료의 내용과 공개 범위를 확인하고 수업에서 사용할 수 있다고 판단했다는 의미다.
- `부분 출석`은 지각과 조퇴를 별도 상태로 나누지 않고 합친 출석 상태를 의미한다.

## 이 문서가 하지 않는 일

이 문서는 기능 요구사항, 기술 구조, API 계약을 상세히 설명하지 않는다. 다음 내용은 각 전용 문서에서 관리한다.

- 화면별 기능
- 필드 목록
- 사용자 흐름
- 권한 매트릭스
- 수락 기준
- MVP 완료 기준
- 데이터베이스 테이블과 RLS 정책
- 서버 action, query, route handler 계약
- 배포와 운영 환경
