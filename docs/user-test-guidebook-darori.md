# 다로리인 유저 테스트 가이드북

이 문서는 Google Form으로 진행하는 다로리인 비동기 유저 테스트의 단일 운영 가이드입니다. 참여자는 각자 배정받은 테스트 계정으로 앱을 조작하고, Google Form에 수행 결과와 사용 경험을 남깁니다.

## 1. 테스트 준비

### 테스트 환경

- 워크스페이스: 참가자별 독립 워크스페이스
  - 예: `다로리인 유저테스트 owner01`, `다로리인 유저테스트 instructor01`
- 앱 URL: `https://dure-user-test-dure-s-projects.vercel.app`
- Supabase 프로젝트: `dure-user-test`
- Supabase project ref: `sufvrkvlpebjeksimfix`
- Supabase URL: `https://sufvrkvlpebjeksimfix.supabase.co`
- 테스트 데이터 생성: 유저 테스트 전용 Supabase 환경변수로 `npm run seed:darori -- --google-form --owner-count 10 --instructor-count 10` 실행
- seed dry-run 확인: `node scripts/seed-darori-user-test.mjs --google-form --owner-count 10 --instructor-count 10 --dry-run`

참여자는 `http://localhost:3000`으로 접속할 수 없습니다. Google Form 안내에는 반드시 배포된 앱 URL을 넣습니다.

### 테스트 계정 배정

| 참가자 ID | 역할 | 이메일 | 비밀번호 | 워크스페이스 |
|---|---|---|---:|---|
| `owner01` - `owner10` | 대표 운영자 | `darori.owner+ownerNN@test.local` | `123456` | `다로리인 유저테스트 ownerNN` |
| `instructor01` - `instructor10` | 강사 | `darori.instructor+instructorNN@test.local` | `123456` | `다로리인 유저테스트 instructorNN` |

참여자 한 명에게는 참가자 ID 1개와 해당 계정 1개만 안내합니다. 서로 다른 참가자가 같은 계정을 쓰면 결과가 섞이므로, Google Form 응답에도 참가자 ID를 반드시 받습니다.

### 준비물

- 업로드 테스트 파일: `녹음 준비 안내.txt`
- 파일 내용 예시:

```text
녹음 전 준비 안내입니다.
각자 맡은 가사를 한 번씩 읽어 보고, 조용한 대기 공간에서 순서를 기다려 주세요.
```

## 2. Seed 데이터 기준

seed 스크립트는 참가자별 워크스페이스마다 다음 데이터를 만듭니다.

| 항목 | 수량 | 비고 |
|---|---:|---|
| 워크스페이스 | 20 | 운영자용 10개, 강사용 10개 |
| 공유 계정 | 20 | 참가자에게 실제 안내하는 계정 |
| 내부 계정 | 워크스페이스당 3 | 대표 운영자, 강사, 그룹 운영자 멤버십 구성용 |
| 마을학교 그룹 | 워크스페이스당 7 | 기존 7개 그룹 |
| 참여자 | 워크스페이스당 32 | 한국어 가명, 각 그룹에 분배 |
| 수업 | 워크스페이스당 9 | 진행 중 5, 완료 2, 진행 전 2 |
| 자료 | 워크스페이스당 2 | `.txt` 자료를 Supabase Storage에 업로드 |
| 기존 출석 | 워크스페이스당 2회차분 | `방과후, 캠핑` 1-2회차 |
| 기존 메모 | 워크스페이스당 2개 | 캠핑/음원출시 수업 메모 |
| 최근 활동 | 워크스페이스당 8개 | 자료, 출석, 메모, 멤버 이벤트 |

수업 수량은 진행 중 5개, 완료 2개, 진행 전 2개로 총 9개입니다.

## 3. 진행자 운영 순서

### 사전 준비

1. 유저 테스트용 Vercel 배포가 `dure-user-test` Supabase 프로젝트를 바라보는지 확인합니다.
2. `APP_URL`이 참여자에게 공유할 배포 URL과 동일한지 확인합니다.
3. 유저 테스트 전용 Supabase 환경변수로 아래 명령을 실행해 운영자용 10개, 강사용 10개 세트를 만듭니다.

```bash
npm run seed:darori -- --google-form --owner-count 10 --instructor-count 10
```

4. seed 출력의 `participant_id,role,email,password,workspace,app_url` 표를 Google Sheet에 붙여 넣습니다.
5. Google Form 응답을 받을 때 `participant_id`를 필수 문항으로 둡니다.
6. 업로드 테스트 파일 `녹음 준비 안내.txt`를 Google Form 설명 또는 파일 다운로드 링크로 제공합니다.
7. 제출 후 DB 확인은 참가자 ID에 해당하는 워크스페이스에서 합니다.

### Google Form 구성

권장 섹션:

1. 안내 및 동의
2. 참가자 ID 확인
3. 로그인 정보 확인
4. 역할별 태스크 수행
5. 수행 완료 체크
6. 사용 경험 평가
7. 자유 의견

필수 문항:

- 참가자 ID를 입력해 주세요. 예: `owner03`, `instructor07`
- 배정받은 역할을 선택해 주세요. `대표 운영자` / `강사`
- 로그인에 성공했나요?
- 배정된 워크스페이스에 들어갔나요?
- 각 태스크를 완료했나요?
- 가장 헷갈렸던 화면이나 문구는 무엇인가요?
- 실제 운영에 쓰려면 꼭 추가되어야 할 정보나 기능은 무엇인가요?

### Google Form 안내문

```text
안녕하세요. 다로리인 유저 테스트에 참여해 주셔서 감사합니다.

아래 앱 URL에 접속해 배정받은 계정으로 로그인한 뒤, 안내된 태스크를 수행해 주세요.

앱 URL: https://dure-user-test-dure-s-projects.vercel.app

참가자 ID: <개별 배정값>
역할: <대표 운영자 또는 강사>
이메일: <개별 배정 계정>
비밀번호: 123456
워크스페이스: <개별 배정 워크스페이스>

테스트 중 정답을 찾으려 애쓰기보다, 실제로 사용한다고 생각하고 편하게 조작해 주세요.
막히거나 헷갈리는 부분은 Google Form에 그대로 적어 주세요.
다른 참가자와 계정을 공유하지 말아 주세요.
```

### 배포 환경변수 기준

```text
NEXT_PUBLIC_SUPABASE_URL=https://sufvrkvlpebjeksimfix.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=<dure-user-test anon key>
SUPABASE_SERVICE_ROLE_KEY=<dure-user-test service_role key>
SUPABASE_JWT_SECRET=<dure-user-test JWT secret>
APP_URL=<참여자에게 공유할 Vercel 배포 URL>
```

`SUPABASE_SERVICE_ROLE_KEY`와 `SUPABASE_JWT_SECRET`은 문서나 채팅에 공개하지 않습니다.

## 4. 운영자 세션

권장 시간: 30-40분  
로그인 계정: `darori.owner+ownerNN@test.local`

### 태스크 1. 운영 현황 파악하기

상황: 여러 마을학교 수업이 동시에 운영되고 있습니다. 전체 운영 현황을 빠르게 확인해야 합니다.

수행:

1. 로그인 후 배정받은 `다로리인 유저테스트 ownerNN` 워크스페이스로 들어갑니다.
2. 왼쪽 메뉴에서 `홈`을 확인합니다.
3. 진행 중인 수업, 최근 활동, 가까운 일정이 어디에 보이는지 살펴봅니다.
4. `참여자·수업 관리`로 이동한 뒤 `수업 관리` 탭을 엽니다.
5. 수업 목록에서 진행 중, 진행 완료, 진행 전 수업이 어떻게 구분되는지 확인합니다.

완료 기준:

- 현재 운영 중인 수업을 말할 수 있습니다.
- 수업 목록에서 상태와 연결 그룹을 확인할 수 있습니다.

관찰 포인트:

- 홈에서 가장 먼저 보는 정보
- 최근 활동과 수업 상태가 현황 파악에 주는 도움
- `참여자·수업 관리` 안에서 `수업 관리` 탭을 찾는 데 생기는 막힘

### 태스크 2. 새 수업 `반찬을 부탁해` 만들기

상황: `노는 엄마들` 마을학교에서 요리 만들기 수업을 새로 운영하기로 했습니다.

수행:

1. `참여자·수업 관리`의 `수업 관리` 탭으로 이동합니다.
2. `새 수업` 버튼을 누릅니다.
3. `수업 이름`에 `반찬을 부탁해`를 입력합니다.
4. `연결 그룹`에서 `노는 엄마들`을 선택합니다.
5. `담당 강사`는 비워둡니다.
6. `운영 상태`는 `진행 전`으로 둡니다.
7. `반복 회차 수업`을 선택합니다.
8. 시작일은 테스트 당일 이후 가까운 날짜로 선택합니다.
9. 시작 시간은 `14:00`, 종료 시간은 `16:00`으로 입력합니다.
10. 반복 요일은 편한 요일 1개를 선택합니다.
11. 종료 조건은 `총 회차 수`, 값은 `4`로 입력합니다.
12. `참여자 배정`에서 `노는 엄마들` 참여자가 후보로 보이는지 확인합니다.
13. 참여자는 기본 선택 상태를 유지합니다.
14. `수업 만들기`를 누릅니다.
15. 목록에서 `반찬을 부탁해`가 생성되었는지 확인합니다.

완료 기준:

- `반찬을 부탁해` 수업이 생성되었습니다.
- `노는 엄마들` 그룹과 참여자가 연결되었습니다.
- 총 4회차 일정이 생성되었습니다.

### 태스크 3. 기존 수업 출석 현황 확인하기

상황: `방과후, 캠핑` 수업의 출석 상태를 확인해야 합니다.

수행:

1. 수업 목록에서 `방과후, 캠핑`을 엽니다.
2. 수업 상세에서 `참여자 현황` 탭을 확인합니다.
3. 참여자별 출석 수, 최근 출석 상태, 특이사항을 살펴봅니다.
4. 자료 또는 홈 탭으로 이동해 수업 정보가 한곳에 모여 있는지 확인합니다.

완료 기준:

- `방과후, 캠핑` 참여자의 출석 현황을 확인했습니다.
- 어떤 참여자가 출석 관리 대상인지 이해했습니다.

### 태스크 4. 수업 자료 확인하고 새 자료 업로드하기

상황: `마을학교 음원출시` 수업에 녹음 준비 안내 자료를 추가해야 합니다.

수행:

1. 수업 목록에서 `마을학교 음원출시`를 엽니다.
2. `수업 자료` 탭으로 이동합니다.
3. 기존 자료 `가사 초안 활동지.txt`를 확인하고 다운로드 버튼을 눌러봅니다.
4. `자료 업로드` 버튼을 눌러 `녹음 준비 안내.txt`를 업로드합니다.
5. 업로드한 자료가 목록에 추가되었는지 확인합니다.

완료 기준:

- 기존 자료를 확인했습니다.
- `녹음 준비 안내.txt`가 수업 자료 목록에 추가되었습니다.

### 태스크 5. 참여자 메모 수정하기

상황: `다로리마을학교` 참여자 중 한 명에게 다음 운영자가 참고할 메모를 남깁니다.

수행:

1. `참여자·수업 관리`로 이동합니다.
2. `참여자 관리` 탭을 선택합니다.
3. 그룹 필터에서 `다로리마을학교`를 선택합니다.
4. 참여자 1명을 고릅니다.
5. `수정` 버튼을 누릅니다.
6. `메모`에 `녹음 활동 참여 의사 높음`을 입력합니다.
7. `저장`을 누릅니다.
8. 목록에서 메모가 반영되었는지 확인합니다.

완료 기준:

- 다로리마을학교 참여자 1명의 메모가 수정되었습니다.
- 참여자 목록에서 메모를 확인할 수 있습니다.

## 5. 강사 세션

권장 시간: 20-30분  
로그인 계정: `darori.instructor+instructorNN@test.local`

### 태스크 1. 담당 수업 확인하기

상황: 강사는 본인이 맡은 수업만 중심으로 확인해야 합니다.

수행:

1. 강사 계정으로 로그인합니다.
2. 배정받은 `다로리인 유저테스트 instructorNN` 워크스페이스로 들어갑니다.
3. `홈`에서 담당 수업 목록을 확인합니다.
4. `마을학교 음원출시`와 `방과후, 캠핑`이 보이는지 확인합니다.
5. `방과후, 캠핑` 수업으로 들어갑니다.

완료 기준:

- 강사가 담당하는 수업 2개를 확인했습니다.
- `방과후, 캠핑` 강사 콘솔에 들어갔습니다.

### 태스크 2. `방과후, 캠핑` 3회차 출석 입력하기

상황: 3회차 수업이 끝났고, 강사는 참여자 출석을 기록해야 합니다.

수행:

1. `출석부` 탭을 엽니다.
2. 회차 선택 영역에서 `3회차`를 선택합니다.
3. 참여자 목록을 확인합니다.
4. 대부분은 `출석`으로 두고, 1명은 `부분 출석`, 1명은 `결석`으로 바꿉니다.
5. 필요하면 참여자별 메모를 입력합니다.
6. `출석 저장`을 누릅니다.

완료 기준:

- 3회차 출석이 저장되었습니다.
- 출석, 부분 출석, 결석 상태가 섞여 있습니다.

### 태스크 3. 수업 메모 작성하고 자료 확인하기

상황: 강사는 회차별 진행 상황을 남기고, 다른 담당 수업의 자료도 확인해야 합니다.

수행:

1. `방과후, 캠핑`의 `출석부` 화면에서 `수업 메모` 영역을 찾습니다.
2. 아래 문장을 입력합니다.

```text
밧줄놀이 활동에 전반적으로 적극적으로 참여했고, 다음 회차에는 안전 안내 시간을 조금 더 확보하면 좋겠습니다.
```

3. `메모 저장`을 누릅니다.
4. 상단 탭 또는 홈을 통해 `마을학교 음원출시` 수업으로 이동합니다.
5. `수업 자료` 탭에서 기존 자료가 보이는지 확인합니다.

완료 기준:

- `방과후, 캠핑` 3회차 수업 메모가 저장되었습니다.
- `마을학교 음원출시` 자료 목록을 확인했습니다.

## 6. 테스트 후 확인 항목

운영자 세션 이후:

- `반찬을 부탁해` 수업이 생성됨
- `노는 엄마들` 참여자가 수업에 배정됨
- `마을학교 음원출시`에 `녹음 준비 안내.txt` 자료가 추가됨
- 다로리마을학교 참여자 1명의 메모가 `녹음 활동 참여 의사 높음`으로 변경됨

강사 세션 이후:
